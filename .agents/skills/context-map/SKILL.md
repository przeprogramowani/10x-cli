# Context map — Wide Scan → Deep Focus

This repo keeps a committed map of itself under `context/map/`, generated by cheap
deterministic CLI tools (git history + import graph) run outside the model's context
window. Read the map first; add a thin Deep Focus for the specific task. Almost never
re-scan the whole repo.

## Step 0 — start from the committed map

- `context/map/repo-map.md` — the synthesized map (start here).
- `context/map/artifact-1-territory.md` / `-2-structure.md` / `-3-contributors.md`.
- `context/map/graph/*` — raw cycles + coupling.

Refresh if missing or the header stamp is old vs `git log`:
`bun run repo-map` (regenerate) · `bun run repo-map:check` (fails if stale).

Trust the map's stated limitations: a co-change is not a hard dependency; anything the
static graph can't see is an `unknown`, not "no dependency".

## Step 1 — Deep Focus (the tailored addition)

Use the map to pick the ONE area the task touches. Pull targeted CLI evidence scoped to
it (focused import graph via `npx madge`/`npx depcruise`, its churn/contributors via
`git log`) rather than bulk file reads. Read the few hub files the graph marks — in this
repo that usually means `src/lib/config.ts`, `src/lib/api-client.ts`, or the command in
play. Verify the map against the code; then answer the actual request.

## Regenerate vs extend

Regenerate (`bun run repo-map`) when modules moved or `:check` reports drift — never
hand-edit the generated files. To change *what* is captured, edit
`tools/repo-map/config.mjs`. Keep task-specific notes next to the work, not in the map.
